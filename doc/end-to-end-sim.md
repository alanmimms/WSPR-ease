# Mixed-Signal Simulation Pipeline: WSPR-ease Transmitter

## 1. Objective
This document outlines the end-to-end simulation pipeline for the
WSPR-ease transmitter. Because the architecture relies on dynamically
re-clocked high-speed digital edge placement from an FPGA to drive a
non-linear analog RF power stage, independent digital or analog
simulations are insufficient.

This hybrid workflow captures the exact phase math, dynamic state
generation, and sub-degree dither from the FPGA gateware (operating
under the "Path B" Phase-Interpolated Ring Counter architecture) and
passes it physically into the analog SPICE domain. This enables
precise calculation of gate drive timings, harmonic suppression, and
MOSFET thermal dissipation prior to commercial PCB fabrication.

---

## 2. Phase 1: Digital Gateware Simulation (Verilator)
The first stage captures the exact physical timing of the digital
logic as it will exit the iCE40UP5K pins.

### 2.1. Testbench Execution
* **Toolchain:** Amaranth Python testbench driving Verilator.
  Verilator allows for cycle-accurate, multi-clock domain simulation.
* **Clocking:** Simulate the system using the exact band-specific
  clock multiple ($F_{clk}$) generated by the Si5351.
    * For bands < 10 MHz (1-2-1 Emission): Clock the simulation at
      **$15 \\times F_{tx}$**.
    * For bands $\\ge$ 10 MHz (Square Wave): Clock the simulation at
      **$5 \\times F_{tx}$**.
* **Stimulus:** Provide the necessary phase modulation offsets and
  allow the 4-stage DSP pipeline to run. This ensures the output
  reflects the true 16-bit phase addition and LFSR dither mapping via
  the `SB_MAC16`.

### 2.2. Data Capture and CSV Export
* Within the Verilator C++ simulation loop (or Amaranth python
  wrapper), monitor the four physical output pins: `rfPushBase`,
  `rfPushPeak`, `rfPullBase`, and `rfPullPeak`.
* Record the state of these pins at every clock edge.

* **Format:** Export the trace to a Piece-Wise Linear (PWL) CSV file.
  The structure must map simulated time to physical voltages (0.0V for
  logic low, 3.3V for logic high). Note that the time steps will vary
  depending on the simulated band.
    ```csv
    Time,      V_PushBase, V_PushPeak, V_PullBase, V_PullPeak
    0.000ns,   0.0,        0.0,        0.0,        0.0
    11.85ns,   3.3,        0.0,        0.0,        0.0
    23.70ns,   3.3,        3.3,        0.0,        0.0
    ```

---

## 3. Phase 2: SPICE Ingestion (The Bridge)
The CSV file acts as the boundary between the digital and analog
domains.

* **Toolchain:** LTspice (or equivalent SPICE simulator).
* **Source Configuration:** Instantiate four independent voltage
  sources.
* Configure each source using the `PWL file` parameter, pointing to
  the respective column in the exported CSV.
* This forces the SPICE simulation to execute the exact digital
  modulation waveform, fully accounting for the Phase-Interpolated
  Ring Counter's state generation, fractional phase overlap, and PRNG
  noise jitter generated by the FPGA.

---

## 4. Phase 3: Analog Chain Modeling
The analog simulation must accurately reflect the parasitic and
dynamic traits of the physical BOM to yield useful data.

### 4.1. Gate Drive and Dead-Time Network
* **Driver:** Use the manufacturer SPICE model for the UCC27524 dual
  gate driver (or a voltage-controlled switch with matched 13ns
  propagation delays and 5A source/sink limits).
* **Analog Shaping:** Include the specific $10\\Omega$ resistor and
  1N4148W diode parallel network on each gate trace. This is critical
  for validating the hardware dead-time wedge that prevents
  shoot-through.

### 4.2. Power Stage (MOSFETs)
* **Components:** Insert the specific SPICE models for the IRLML2060
  or MMBF170 FETs.
* **Parasitics:** Ensure the models include accurate non-linear gate
  capacitance ($C_{iss}$), drain-to-source capacitance ($C_{oss}$),
  and body diode recovery metrics. Do not use generic ideal switches.

### 4.3. Output Transformer
* **Inductive Coupling:** Model the push-pull center-tapped
  transformer using mutually coupled inductors (e.g., `K1 L_primary1
  L_primary2 L_secondary 0.98`).
* **Leakage:** The coupling coefficient ($K$) must be less than 1.0. A
  realistic $K$ value (e.g., 0.95 to 0.98) models leakage inductance,
  which is required to accurately simulate the high-voltage flyback
  spikes on the MOSFET drains.

### 4.4. Low Pass Filters (LPF)
* **Topology:** Model the band-specific 5th-order or 7th-order
  Chebyshev LC filter banks.
* **Real Components:** Add Equivalent Series Resistance (ESR) to the
  50V C0G capacitors and series DC resistance (DCR) to the wirewound
  inductors to accurately model insertion loss and thermal dissipation
  in the filter.

## 5. Phase 4: Validation and Analysis Targets
Execute transient (.tran) analysis in LTspice over a sufficient
timeframe (e.g., 20-50 RF cycles) to calculate the following metrics:

1.  **Shoot-Through Verification:**
    * Plot the currents through both the Push and Pull MOSFETs
      simultaneously. Confirm that the $10\\Omega$/1N4148W delay
      network prevents simultaneous conduction across the center tap
      under both 1-2-1 and Square wave modes.
2.  **Drain Voltage Margins ($V_{DS}$):**
    * Probe the MOSFET drain nodes. Ensure that the flyback voltage
      spikes remain strictly below the 60V absolute maximum rating of
      the IRLML2060/MMBF170 under a matched $50\\Omega$ load.
3.  **Thermal Dissipation:**
    * In LTspice, Alt-click the MOSFET components to plot
      instantaneous power ($V_{DS} \\times I_D$).
    * Ctrl-click the power trace label to calculate the average power
      dissipation. Verify this average is near or below the
      125mW/device budget calculated in the thermal assessment.
4.  **Spectral Purity (FCC Compliance):**
    * Perform an FFT on the voltage across the $50\\Omega$ dummy load.
    * Measure the fundamental carrier power against the 3rd, 5th, and
      7th harmonics.
    * Validate that spurious emissions are suppressed by at least
      **-43 dBc**. This is especially critical when running the Square
      wave emission simulations on the upper bands, as the physical
      LPF is solely responsible for clearing the 3rd harmonic without
      digital cancellation help.
